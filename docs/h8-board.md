# H8/3069F の基板の書き込みと、検証のための改造

参照実装のファームウェア(`c/h8/`)を H8/3069F の基板に書き込む方法と、検証を繰り返しやすくするために加えた改造をまとめる。

**この改造は検証のためのものであり、OLDP の規格には含まれない。** 規格は、機器のソフトウェアの更新を範囲外としている(規格の 1 章。必要な機器は 11 章の拡張で扱う)。

## 1. 基板の本来の書き込み方

この基板は、DIP スイッチ(1-4 番)でマイコンの動作モードを選ぶ。1-3 番はモードの端子、4 番はフラッシュの書き換えを許す FWE の端子につながっている。

本来の使い方は、次のとおりである。

1. 書き込むときは、スイッチをブートモードの位置(ON・ON・OFF・ON)にして電源を入れる。マイコンに内蔵のブートプログラムが動き、シリアルからフラッシュ全体を書き込める(`tools/kz_h8write.ps1`)。
2. 動かすときは、スイッチを動作の位置にして電源を入れ直す。4 番を OFF(FWE=0)にすれば、動作中にフラッシュは書き換えられない。

この方法では、書き込むたびに、スイッチの切り替えと電源の入れ直しが要る。

## 2. 検証のための改造

検証では、ファームウェアを直しては書き込み、起動し直して確かめることを何度も繰り返す。そのたびにスイッチを切り替えずに済むよう、次の 4 点を加えた。

| 改造 | 中身 | 関わるファイル |
|---|---|---|
| 更新の仕組み | フラッシュの先頭のブロック(EB0)に置く小さなプログラム。リセットのたびに 500 ms だけシリアルから合図(`OLDPLOAD`)を待ち、来なければ本体へ飛ぶ。合図が来たら、マイコンのユーザープログラムモードで本体を書き換える | `c/h8/loader/` |
| 本体の置き場所 | 本体を、EB0 の後ろの 0x1000 番地からに置いた | `c/h8/rom.ld` |
| ソフトウェアのリセット(`reset` コマンド) | 起動の入口(0x100 番地)へ飛ぶ。電源の入れ直しやリセットボタンを使わずに、起動し直せる | `c/h8/main.c` |
| 本体の書き換え(`update` コマンド) | 更新の仕組みへ移り、PC の `tools/h8-update.ps1` から本体を書き換える。スイッチは動作の位置のままでよい | `c/h8/main.c`・`tools/h8-update.ps1` |

ユーザープログラムモードでフラッシュを書き換えるには、FWE が 1 である必要がある。そのため、この改造では、スイッチの 4 番を ON にしたまま動かす(ON・OFF・ON・ON。モード 5、FWE=1)。

更新の仕組みは、PC からの次の手順に答える(9600 bps。答えは成功なら `K`、失敗なら `N` と番号)。

| 手順 | 中身 |
|---|---|
| `E` | 本体の範囲を消去する(EB0 は消さない) |
| `W` | 128 バイトずつ書き込み、読み直して確かめる(番地と中身に CRC-32 を付ける) |
| `R` | フラッシュの中身を読み出す(調べるため) |
| `V` | 書いた範囲を読み直し、CRC-32 を比べる |
| `G` | 本体へ飛ぶ |

## 3. フラッシュの配置

| 場所 | 中身 | 本体の書き換え(`update`)で |
|---|---|---|
| EB0(0x000000-0x000FFF) | 更新の仕組み | 残る |
| 0x001000 から | 本体(約 46 KB) | 書き換わる |
| EB14(0x060000 から) | 交換した機器の鍵(標準の拡張 OLDPKEY) | 残る |
| EB15(0x070000 から) | 覚えたホスト、LAN の設定 | 残る |

更新の仕組みは、本体の大きさの分だけ EB1 から消すので、EB14・EB15 は残る。ブートモードでの書き込み(`kz_h8write.ps1`)は、フラッシュ全体を消すので、全て消える。

## 4. 使い方

| 場面 | 方法 |
|---|---|
| 初めて書き込むとき、更新の仕組みを変えたとき | スイッチをブートモードの位置にし、`tools/kz_h8write.ps1` で `c/h8/oldp-h8-all.mot`(更新の仕組みと本体を合わせたもの)を書く。その後、スイッチを ON・OFF・ON・ON に戻す |
| 本体だけを書き換えるとき | スイッチはそのままで、`pwsh -File tools/h8-update.ps1 -Port <シリアルポート>` |
| 本体が壊れて `update` コマンドが使えないとき | `tools/h8-update.ps1` に `-Recover` を付けて実行し、基板のリセットボタンを押す。更新の仕組みが合図を受けて、書き換えに移る |
| 起動し直したいとき | 本体の `reset` コマンド |

## 5. 注意

- **製品には使わない:** 更新の仕組みは、シリアルから受けたデータを CRC-32 で確かめるだけで、署名は確かめない。シリアルの線にさわれる人なら誰でも、本体を書き換えられる。製品の機器では、署名を確かめる更新の仕組みを持つか、規格の 11 章の拡張で更新を扱う。
- **フラッシュは常に書き換えられる状態にある:** FWE=1 のまま動かすので、本体の不具合でフラッシュを壊すおそれがある。壊れても、ブートモードで書き直せば戻る。
- **同じ基板で本来の使い方に戻すとき:** スイッチをブートモードの位置にして、使いたいファームウェアを `kz_h8write.ps1` で書き込む。ブートモードの書き込みはフラッシュ全体を消すので、更新の仕組みも消える。その後の動作の位置は、そのファームウェアの説明に従う。
