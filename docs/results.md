# 参照実装のテストと確認の結果

OLDP(Optical Lab Device Protocol)第 1.0 版の参照実装について、テストの内容、H8/3069F の基板で測った値、実装の制限、確かめていないことをまとめる。規格の本文は、規格のリポジトリ [optical-lab-device-protocol](https://github.com/NrivYuki/optical-lab-device-protocol) の `docs/spec.md` にある。

機器の側は C で書いた。動的なメモリ確保はしない。暗号の部品は、ChaCha20-Poly1305 に Monocypher 4.0.3 を使い、X25519 は 16 ビットの CPU 向けに `c/src/oldp_x25519.c` を、SHA-256 は `c/src/oldp_sha256.c` を書いた。ホストの側は JavaScript で書き、vca-hub の拡張で使う。

## テスト

このリポジトリのテスト:

| 対象 | 内容 |
|---|---|
| JavaScript | `spec/vectors` の全て、セッションのバイト列(機器の側・ホストの側)、UART の再送とやり直し、誤りの扱い、UART の使用中に暗号で確かめられないフレームを捨てること、`REQUIRE=`、接続数の上限、`spec/` が規格のリポジトリと同じであること |
| C | SHA-256(FIPS 180)、HMAC(RFC 4231)、X25519(RFC 7748 の例・1000 回の繰り返し・Monocypher との比較)、ChaCha20-Poly1305(RFC 8439)、`spec/vectors` の全て(TCP・UART のセッションのバイト列を含む)、機器の誤りの扱い、UART の使用中に暗号で確かめられないフレームを捨てること、`REQUIRE=`、線の上でフレームが失われたり壊れたりしたときの再送 |

vca-hub を通した確認([vca-hub-extension](https://github.com/NrivYuki/vca-hub-extension) のリポジトリ):

| 対象 | 内容 |
|---|---|
| vca-hub の拡張のテスト | DCS の機器と OLDP の機器の間の両方向の受け渡し、送り先への送信、加工条件の拡張との併用、AVAIL、同じ PUT の 2 度目、受けられない値、拡張の受け口、OLDPKEY |
| `tools/verify-device.js` | このリポジトリの C の模擬機器(UART・TCP)と H8 の基板(UART・LAN)を vca-hub とつなぎ、ペアリング(両側の受付と解除)・PUT・GET・RESULT・TIME・PING(両方向)・INFO・AVAIL(接続したとき・接続している間)・受けられない値・1440 点の玉型を確かめる。H8 の基板では、標準の拡張 OLDPKEY による鍵の交換と、再起動した後も新しい鍵が残ることも確かめる |

## H8/3069F で測った値

H8/3069F(20 MHz)で測った値である。UART では、9600 bps で PC の中継を通して vca-hub へつないだ。LAN では、10BASE-T(RTL8019AS)で PC と直結し、vca-hub へ TCP でつないだ。

| 項目 | UART | LAN |
|---|---|---|
| プログラムの大きさ | 45.6 KB(暗号・TCP/IP・項目の辞書・約 2 KB の見本のジョブを含む) | UART と同じ |
| RAM(変数) | 7.2 KB(フレームの上限 512 バイト。スタックを除く) | UART と同じ(TCP の受信には UART の作業領域を使う) |
| X25519 の 1 回の計算 | 5.7 秒 | UART と同じ |
| PUT 1 回のセッション(片眼 360 点、約 2 KB) | 28 秒(うちハンドシェイクが約 25 秒) | 24.4 秒 |
| GET と RESULT のセッション(両眼 360 点) | 43 秒 | 24.7 秒 |
| 1 つのセッションで TIME・PING・PUT・GET・RESULT・INFO | 47 秒 | 25.0 秒 |
| GET と RESULT のセッション(両眼 1440 点) | 90-93 秒 | 27 秒 |

## 制限

- H8 の基板のソフトウェアの更新では、シリアルから受けたデータを CRC-32 で確かめるだけで、署名は確かめない(検証を繰り返しやすくするための改造。[h8-board.md](h8-board.md))。
- 機器の鍵は、組み立てのときにファームウェアへ埋め込んだ 1 つの鍵から始まる(標準の拡張 OLDPKEY で替えられる)。製造の工程で機器ごとに鍵を入れる手順は持たない。

## 確かめていないこと

- 基板のリセットボタンによる起動(電源の入れ直しと、起動の入口へ飛ぶコマンドでは確かめた)
- PC の中継を挟まずに、機器とホストを線で直結した形
- LAN での再送(確認の間に、パケットの欠落が起きなかった)
- スイッチやルーターを挟んだ LAN(PC との直結では確かめた)
- DHCP(H8 の基板はアドレスを設定して使う。DHCP は実装していない)
- 9600 bps より速い UART
- この実装以外の実装との相互接続
- 基板の乱数の統計的な質
- 自作の X25519(`c/src/oldp_x25519.c`)の処理時間が、秘密の値によって変わらないかどうか
- 暗号の部分の第三者による評価
- UART の線に実際に割り込む相手に対する基板の動作(暗号で確かめられないフレームを捨てる決まりは、C と JavaScript のテストで確かめた)
